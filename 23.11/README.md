## 1. Выявление аномалий

1. **Аномалия вставки:** нельзя добавить в базу новое блюдо (с категорией и составом) или нового официанта, пока не оформлен хотя бы один чек с ним.
2. **Аномалия обновления:** если Петров А.А. перейдёт в вечернюю смену, придётся изменить смену во всех его чеках (1001, 1003 и всех последующих); пропуск хотя бы одной строки нарушит целостность данных.
3. **Аномалия удаления:** при удалении чека №1002 из базы полностью исчезнет информация о блюде «Цезарь», его категории, цене и составе.

## 3. Приведение ко 2-й нормальной форме (2НФ)

**Требование:** отношение находится в 1НФ, и каждый неключевой атрибут полностью зависит от всего составного ключа (нет частичных зависимостей).

**Функциональные зависимости:**

- `Номер_чека -> Номер_стола, Дата, Официант_ФИО, Смена_официанта` — зависит от части ключа;
- `Блюдо -> Цена, Категория` — зависит от части ключа;
- `(Номер_чека, Блюдо) -> Кол-во` — зависит от части ключа (без `Ингредиент`);
- ингредиент — свойство блюда, а не чека: связь `Блюдо — Ингредиент` имеет вид «многие ко многим».

**Декомпозиция на 4 таблицы:**

1. `Checks` (`check_id` PK, `table_no`, `check_date`, `waiter_name`, `waiter_shift`)
2. `Dishes` (`dish_id` PK, `dish_name`, `current_price`, `category_name`)
3. `Check_Items` (`check_id` PK/FK, `dish_id` PK/FK, `quantity`, `unit_price`) — цена фиксируется на момент продажи
4. `Dish_Ingredients` (`dish_id` PK/FK, `ingredient_name` PK)

## 4. Приведение к 3-й нормальной форме (3НФ) и НФБК

**Требование:** отношение находится во 2НФ, и отсутствуют транзитивные зависимости неключевых атрибутов.

**Транзитивные зависимости и дублирование:**

- В таблице `Checks`: `check_id -> waiter_name -> waiter_shift`. Смена зависит не от чека, а от официанта, поэтому официант выносится в отдельную таблицу `Waiters`.
- В таблице `Dishes`: название категории вынесено в справочник `Categories`. Строго по определению 3НФ это не обязательно (категория зависит от блюда напрямую), но справочник исключает дублирование и опечатки в названиях.
- В таблице `Dish_Ingredients` название ингредиента повторяется у разных блюд («Говядина» есть и в борще, и в стейке), поэтому ингредиенты выносятся в справочник `Ingredients`.

**Итоговая схема в 3НФ (7 таблиц):**

1. `Waiters` (`waiter_id` PK, `full_name`, `shift`)
2. `Categories` (`category_id` PK, `category_name`)
3. `Dishes` (`dish_id` PK, `dish_name`, `current_price`, `category_id` FK)
4. `Ingredients` (`ingredient_id` PK, `ingredient_name`)
5. `Dish_Ingredients` (`dish_id` PK/FK, `ingredient_id` PK/FK)
6. `Checks` (`check_id` PK, `table_no`, `check_date`, `waiter_id` FK)
7. `Check_Items` (`check_id` PK/FK, `dish_id` PK/FK, `quantity`, `unit_price`)

**Проверка НФБК:** во всех отношениях детерминанты функциональных зависимостей являются потенциальными ключами: `waiter_id`, `category_id`, `dish_id` (а также `dish_name`, `category_name`, `ingredient_name`, объявленные `UNIQUE`), `ingredient_id`, `check_id`, пара `(check_id, dish_id)`. Составные ключи `Dish_Ingredients` не содержат неключевых атрибутов. Следовательно, схема находится и в НФБК, дополнительная декомпозиция не требуется.

## 5. Реализация нормализованной схемы на SQL (PostgreSQL)

```sql
CREATE SCHEMA IF NOT EXISTS restaurant_3nf;
SET search_path TO restaurant_3nf, public;

-- 1. Официанты
CREATE TABLE waiters (
    waiter_id SERIAL PRIMARY KEY,
    full_name VARCHAR(120) NOT NULL,
    shift VARCHAR(10) NOT NULL CHECK (shift IN ('Дневная', 'Вечерняя'))
);

-- 2. Справочник категорий блюд
CREATE TABLE categories (
    category_id SERIAL PRIMARY KEY,
    category_name VARCHAR(80) NOT NULL UNIQUE
);

-- 3. Меню (блюда)
CREATE TABLE dishes (
    dish_id SERIAL PRIMARY KEY,
    dish_name VARCHAR(150) NOT NULL UNIQUE,
    current_price NUMERIC(10, 2) NOT NULL CHECK (current_price >= 0),
    category_id INT NOT NULL REFERENCES categories(category_id) ON DELETE RESTRICT
);

-- 4. Справочник ингредиентов
CREATE TABLE ingredients (
    ingredient_id SERIAL PRIMARY KEY,
    ingredient_name VARCHAR(100) NOT NULL UNIQUE
);

-- 5. Состав блюд (разрешение связи M:N)
CREATE TABLE dish_ingredients (
    dish_id INT NOT NULL REFERENCES dishes(dish_id) ON DELETE CASCADE,
    ingredient_id INT NOT NULL REFERENCES ingredients(ingredient_id) ON DELETE RESTRICT,
    PRIMARY KEY (dish_id, ingredient_id)
);

-- 6. Чеки
CREATE TABLE checks (
    check_id INT PRIMARY KEY,  -- номер чека
    table_no SMALLINT NOT NULL CHECK (table_no > 0),
    check_date DATE NOT NULL DEFAULT CURRENT_DATE,
    waiter_id INT NOT NULL REFERENCES waiters(waiter_id) ON DELETE RESTRICT
);

-- 7. Позиции чека (разрешение связи M:N между чеками и блюдами)
CREATE TABLE check_items (
    check_id INT NOT NULL REFERENCES checks(check_id) ON DELETE CASCADE,
    dish_id INT NOT NULL REFERENCES dishes(dish_id) ON DELETE RESTRICT,
    quantity SMALLINT NOT NULL CHECK (quantity > 0),
    unit_price NUMERIC(10, 2) NOT NULL CHECK (unit_price >= 0),
    PRIMARY KEY (check_id, dish_id)
);
```

Удалённое при нормализации поле `Сумма` вычисляется запросом:

```sql
SELECT check_id, SUM(quantity * unit_price) AS total
FROM check_items
GROUP BY check_id;
```
